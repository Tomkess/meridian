# Vision

Meridian is the layer that remembers across repositories. Any assistant can help
you build one feature in one repo; none can tell you what you decided six months
ago in a different project, or what is in flight across all ten. Meridian holds
the two things that do not fit inside a single repository's context: a **research
corpus bound to the specs it justifies**, and a **portfolio view of every
project's work in flight**. The spec pipeline exists so both have something to
attach to — it is the scaffolding, not the product.

---

**How to use this file:**
- Keep it to one paragraph — if it needs more, it's a strategy doc, not a vision.
- Read it before creating a new goal (`/goal new`).
- Run `/vision` to update it via guided conversation.
- Every goal, feature, and decision should be traceable back to this.
